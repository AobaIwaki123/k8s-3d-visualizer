# UI改善提案: インタラクティブ・ダッシュボード機能

このドキュメントでは、k8s-3d-visualizer の視認性と操作性を向上させるための3つの主要なUI改善案について詳述します。

## 1. タイムライン・ヒストリー再生 (Timeline Playback)

クラスタの状態変化を時系列で追体験するための機能です。

### 目的
- 障害発生時の前後関係の把握。
- 新規デプロイメントによる Pod の増減や、ローリングアップデートの挙動を可視化。

### UI/UX デザイン
- **シークバー**: 画面下部に全幅のタイムラインスライダーを配置。
- **タイムスタンプ表示**: 現在表示しているデータの取得時刻を表示。
- **再生/一時停止ボタン**: 自動で時間を進め、Pod がポコポコと生成・削除される様子をアニメーションで表示。

### 技術的要件
- `cluster-state.json` を単一のスナップショットから、スナップショットの配列（`history: []`）に拡張。
- タイムライン操作時に、既存の `pods`, `services` を再配置または差分更新するロジックの実装。

---

## 2. ステータス・ポップオーバー (Status Popover)

画面右上の統計情報（Stats）を詳細化し、異常を素早く検知・ドリルダウンするための機能です。

### 目的
- クラスタ全体の「健康状態」の即時把握。
- 異常が発生しているオブジェクトへの迅速なアクセス。

### UI/UX デザイン
- **トリガー**: 右上の `10 pods` などのテキストにホバーまたはクリック。
- **ポップオーバー表示**: 以下の内訳を表示するカード型のフローティングパネル。
    - **Pod 状態内訳**: Running (緑), Pending (黄), Failed (赤) のカウント。
    - **異常リスト**: Failed 状態の Pod 名をリスト表示。
- **インタラクション**: リスト内の Pod 名をクリックすると、カメラがその Pod へ自動でズーム（Focus）し、詳細パネルを表示。

### 技術的要件
- 既存の `setupHoverHandler` または標準的な DOM イベントで実装。
- `fitCamera` 関数を利用したスムーズな視点移動の連携。

---

## 3. リソース・ミニバー (Resource Mini-bars)

クラスタ全体の CPU やメモリの消費状況を、3D 空間の邪魔にならない形で常時表示します。

### 目的
- リソースの逼迫状況と、3D 空間上の Pod 配置（密度）の相関を直感的に理解。

### UI/UX デザイン
- **配置**: トップバーの統計情報の隣、または詳細パネル内。
- **形状**: 高さ 4~6px 程度の細身のプログレスバー。
    - **CPU**: シアン（水色）のバー。
    - **Memory**: パープル（紫）のバー。
- **アラート演出**: 使用率が 80% を超えるとバーの色をオレンジ、90% で赤に変化させる。

### 技術的要件
- データ抽出スクリプト（`scripts/extract-k8s-data.js`）で、Node ごとの Capacity と Usage を集計し、JSON に含めるよう拡張。
- CSS によるアニメーション付きのプログレスバー実装。
