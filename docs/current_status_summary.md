# 現状の可視化仕様まとめ (2026-05-02)

PoCフェーズにおいて、実データに基づいた大規模構成の視認性を向上させるため、以下のレイアウトおよび接続仕様を実装しました。

## 1. 空間レイアウトの階層構造

シーンを垂直方向に3つの層で構成し、役割に応じた配置を行っています。

*   **Workload層 (Y=0)**: 
    *   通常のアプリケーション Pod、Service、Namespace Zone が配置されるメインの階層。
    *   Namespace ごとに水平方向 (X軸) に並べられ、サイドバーからのフォーカス切り替えに対応。
*   **Storage層 (Y=-3)**:
    *   `isStorage` フラグを持つ Pod (Rook-Ceph等) が配置される地下階層。
    *   **動的追従機能**: 選択された Namespace の真下に Ceph Pod 群が自動的に移動・整列し、アプリケーションの「土台」として機能する。
*   **Ingress層 (Y=10/12)**:
    *   外部流入 (Cloudflare等) を扱う階層。現在は機能オプトアウト中だが、上空に配置される設計。

## 2. 接続線 (Connections) の仕様

*   **ストレージパイプライン**:
    *   アプリケーション Pod から地下の Storage層へ伸びるシアン色のライン。
    *   **Nodeベースの接続**: Pod が稼働している物理 Node を判別し、同じ Node 上にある Ceph Pod へと線を結ぶ。これにより物理的な構成（どのサーバーのディスクを使っているか）を表現。
*   **Service-Pod 接続**:
    *   標準的な Service からターゲット Pod への水平方向の接続。
*   **非表示設定 (一旦停止中)**:
    *   Cloudflare および監視網 (Observability) の大規模な網状接続は、視認性確保のため現在は描画をスキップ。

## 3. インタラクションとUX

*   **Namespace フォーカス**: 
    *   サイドバーで選択した Namespace のみを強調表示し、他を非表示にする。
    *   カメラは選択された範囲と、その真下にある Ceph層の両方が収まるように自動調整される。
*   **カメラアングル**:
    *   初期視点を「斜め上 (3/4アングル)」に固定し、奥行きと階層構造が直感的にわかるように調整。

## 4. コード管理方針

*   **モジュール化**: `IngressLayer`, `MonitoringLayer`, `StorageLayer` などの独立したクラスで演出を管理し、`poc.js` 側で簡単に脱着（オプトアウト）できる構造を維持。
*   **メタデータ駆動**: 名前空間名などの文字列ではなく、データ抽出時に付与した `isStorage`, `isIngress` などのフラグを基準にロジックを制御。

## 5. 今後の拡張予定 (UI/UX)

以下の機能について、実装の検討および設計が進められています。詳細は [09_ui_improvement_ideas.md](./09_ui_improvement_ideas.md) を参照してください。

1.  **タイムライン・ヒストリー再生**: クラスタの過去状態をスライダーで遡る機能。
2.  **ステータス・ポップオーバー**: 統計エリアから異常 Pod へ即座にフォーカスするドリルダウン機能。
3.  **リソース・ミニバー**: クラスタ全体の CPU/メモリ使用率を常時監視する視覚インジケーター。
